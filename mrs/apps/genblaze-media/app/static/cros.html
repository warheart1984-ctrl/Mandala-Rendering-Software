CROS · Cinematic Render Operating System

Reference architecture for a governed cinematic render stack, versioned at 0.1.0 under mrs/packages/cros. Seven typed lineage artifacts, six constitutional invariants (CI-001…CI-006), and two conformance profiles that refuse a single meaning of the word “reproducible”.

Status honesty (Drive-G-1). CROS is a reference-architecture scaffold. Its runtimeStatus is absent — there is no CROS runtime, scheduler, adapter host, or farm planner. Every invariant below is at most partial: a validator function that a caller must invoke deliberately. Nothing on this page describes a runtime gate.

Boundary. This page is documentation served by the Genblaze media host. It is not a claim that mrs/apps/genblaze-media implements CROS — that app does not, and no Python module here imports cros. CI-006 bans the reverse direction too: CROS may not import app, genblaze, story_forge, or storyforge, and an import scan checks it. CROS carries no Story Forge lineage.

Constitutional invariants · CI-001…CI-006

Each invariant names a validator in cros.validation. All six are implemented and unit-tested; none is invoked by a production execution path, because no adapter exists. partial is the ceiling until an adapter runs.

What the chain buys — and what it does not

  • Does detect a missing, reordered, or post-hoc-edited stage.
  • Does detect an artifact body edited after its successor was written.
  • Does not prove the described events happened. A caller who fabricates all seven artifacts consistently produces a chain that validates. Lineage integrity is a tamper-evidence property, not an attestation. Binding the chain to a signing authority is a future increment and is declared only.

contentHash is SHA-256 over canonical JSON of the artifact body with the contentHash key excluded — UTF-8, keys sorted, no insignificant whitespace. Implementation: cros.artifacts.canonical_hash. Chain walk: cros.validation.validate_lineage. Schemas: seven JSON Schema Draft 2020-12 files under mrs/packages/cros/schemas/, unit-validated.

The split between stages 5 and 6 is CI-004: “the renderer exited zero” and “we can prove what it produced” are different claims, so they are different artifacts. The split between 6 and 7 is CI-005: evidence claims a reproduction class; a ReplayRecord tests it.

Dual conformance profiles · replay honesty

The load-bearing distinction in CROS: “reproducible” means different things for a seeded offline path tracer and a hosted diffusion endpoint. Collapsing both into one word is the dishonesty the profiles exist to prevent.

Profile Status Permitted replayClass What it actually means
cros.dcc-offline declared bit-identical, deterministic-parameters Expectations placed on a future offline path-tracer adapter — environment lock, seed pinning, sample-count pinning, deterministic reduction order, scene content addressing, OCIO declaration, denoiser disclosure. No adapter exists. No Cycles / Arnold / RenderMan / Karma / Redshift / OIDN / ACES integration, and no stub pretending to be one. Honest default class is deterministic-parameters, because permitting bit-identical is not the same as having observed byte equality.
cros.gen-ai-nim skeleton provider-contract only Pinned model id + params-as-submitted + prompt SHA-256 + seed-if-exposed + provider request id + asset SHA-256 hashed on receipt. Reproducible within the provider contract. Pixel equality is not asserted; a frame-exact claim is a CI-005 failure. A plan deriver and evidence builder exist and are unit-tested — but no adapter calls any provider, and nothing in the package sends a network request.

Why bit-identical is forbidden for hosted inference

  • The provider controls weights, scheduler implementation, batch composition, kernel library, and hardware. None are pinnable from the client, and any may change without a version bump.
  • A recorded seed narrows but does not close the gap: identical seed plus identical params can still diverge across server-side model or runtime revisions.
  • seed: null (provider exposed no seed) and an absent seed field (not applicable) are distinct facts and must not be conflated — which is why presence-with-null is required rather than optional.

Machine-checked for cros.gen-ai-nim only, by cros.evidence.build_evidence and cros.validation.check_profile_evidence_fields. The offline field set is not machine-checked, because no producer exists to check.

Adjacent: 4DRS / RT4D renderer invariant stack

A separate lineage from CROS — do not merge them into one compliance blob. The renderer stack formalises the layer between mathematical theory and 4DRS runtime: PI-* (constitutional physical invariants) → EI-* (runtime guarantees) → M-* (observable measurements) → validation predicates → evidence records.

What CROS is not

  • Not a running runtime, scheduler, or farm planner.
  • Not an Arnold / Cycles / RenderMan / Karma / Redshift / OIDN / ACES implementation.
  • Not a claim that mrs/apps/genblaze-media implements CROS. That app is untouched by the package.
  • Not Story Forge. story_forge / storyforge imports are banned and scanned under CI-006.
  • Not a replacement for the MRS charter. CROS is subordinate to constitution/CHARTER.md and engine/constitution/, and modifies neither.
