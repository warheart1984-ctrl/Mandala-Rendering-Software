Stills · NIM FLUX or RT4D

Use this as the public demo entrypoint: start from a strong concept plate, then optionally trigger the scene reveal lane below.

Pick a visual thesis Choose a prompt that emphasizes geometry, light, material, and scale before narrative detail.
Generate the concept still FLUX sells mood fast; RT4D sells deterministic structure and a stronger technical story.
Reveal the scene interpretation Turn on the dual path so the audience sees concept art and the MRS frame side by side.

Prompt tips (FLUX.1-schnell): abstract geometry, mandalas, tesseracts, neon grids, and studio-lit objects usually work. Photoreal people / faces / skin often return blank black stills on this NIM path — describe the object and light, not a portrait. If a people-like prompt blanks, the service retries once with an abstract rewrite (disable with GENBLAZE_ABSTRACT_RETRY=0). Do not append feedback like “ok this not good” into the prompt.

RT4D renderer backend (GENBLAZE_IMAGE_BACKEND=rt4d, or NVIDIA fallback via GENBLAZE_IMAGE_FALLBACK_TO_RT4D=1): the prompt selects a procedural 4D scene archetype (keyword → surface / palette / camera), then the MRS RT4D CPU path tracer renders a deterministic PNG. Mandala / neural-lattice / sovereign / glyph prompts map to the neural-lattice archetype (radial lattice + energy core primitives) — still not photoreal diffusion. Same prompt → same seed → same bytes. Requires Node.js + renderer-core/scripts/render-still.mjs; see rt4d.available in /health for whether this running image has them. Default quality is draft (safe on shared CPU); choose final only when you can wait longer.

Recommended structure: subject + material + light + camera angle. If you want a full demo moment, check the scene-interpret option before you hit Generate.

Image → MRS scene

This is the reveal lane. Use the generated still above or your own source image, then let the app show the interpreted MRS frame as the second act.

Scene interpretation + path-traced full frame. Upload a photo or paste a prior generate run_id. The service emits a SceneSpecification (NIM vision when configured, else heuristic), validates it, then MRS path-traces a full PNG. This is not geometric reconstruction, depth recovery, or mesh from photo. Default quality is draft (smaller / noisier, typically tens of seconds on CPU) — choose final only when you can wait longer for a nicer still. After an RT4D generate, use Send RT4D still → NVIDIA (or POST /api/rt4d-to-nvidia) to require NIM vision with no silent heuristic fallback — if NVIDIA is down, the RT4D still stays usable.

Best live demo move Generate a concept above, keep the same run id, and immediately interpret it here so the audience sees the bridge between image and structured scene output.
What to say aloud This is scene interpretation, not mesh reconstruction: the point is governed structure plus render continuity, not fake geometry claims.

NIM Cosmos · video (CMM-NIM-Cosmos)

Prompt tips (Cosmos text-to-world): abstract / world-scale scenes (landscapes, geometry, light) work better than portraits. People and faces may blank or degrade. NVCF cold-start: Cosmos is often slower than FLUX on the first hit after Render or NIM idle — even with 600s+ timeouts, expect longer first-request latency; keep this tab open. Larger mp4 objects cost more B2 Class C traffic. This section is hidden by default (stills-only demo); it appears only when the operator explicitly sets GENBLAZE_VIDEO_ENABLED=1.
