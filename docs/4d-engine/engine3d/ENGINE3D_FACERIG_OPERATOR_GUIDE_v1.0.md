# ENGINE3D_FACERIG_OPERATOR_GUIDE_v1.0

Operator guide for upgrading face GLB assets without changing Engine3D APIs or code.

| Field | Value |
|-------|--------|
| Version | 1.0 |
| Status | **Declared** (operator sculpt quality). Resolver + fixture path **enforced** by `test:face` |
| Related | [ENGINE3D_FACE_STRUCTURE_SPEC_v1.0](./ENGINE3D_FACE_STRUCTURE_SPEC_v1.0.md) · [ENGINE3D_FACE_RIG_SCHEMA_v1.0](./ENGINE3D_FACE_RIG_SCHEMA_v1.0.md) · [ENGINE3D_FACE_TIMELINE_SPEC_v1.0](./ENGINE3D_FACE_TIMELINE_SPEC_v1.0.md) · [ENGINE3D_FACE_TOPOLOGY_CHECKLIST_v1.0](./ENGINE3D_FACE_TOPOLOGY_CHECKLIST_v1.0.md) · [ENGINE3D_FACE_BLENDER_EXPORT_PRESET_v1.0](./ENGINE3D_FACE_BLENDER_EXPORT_PRESET_v1.0.md) |

> **Drive-G-1:** In-repo `HumanFace*.glb` files are **fixtures** (low tris). Production 20k–40k sculpts are **operator drop-ins** under `operator-assets/human/` — not invented or committed in this repository.

## 1. Purpose

Define how operators upgrade face assets (GLB) without changing Engine3D APIs or logical filenames.

## 2. Asset Paths

Stable **logical** filenames (MUST NOT change):

| Logical file | Role |
|--------------|------|
| `HumanFaceNeutral.glb` | Neutral face mesh |
| `HumanFaceRigged.glb` | Rigged mesh + bones + blendshapes |

### Resolution order (runtime)

Engine3D resolves via `resolveHumanFacePath(name)`:

1. **Operator override:** `${OPERATOR_ASSETS_ROOT}/human/<Name>.glb`
2. **CI fixture:** `mrs/assets/human/<Name>.glb` (Docker image: `/app/assets/human/`)

| Env / path | Semantics |
|------------|-----------|
| `OPERATOR_ASSETS_ROOT` | Defaults to `./operator-assets`. Absolute values used as-is. Relative values resolve against the **repo/install root** (directory containing `mrs/assets/human`, `assets/human`, or `constitution/CHARTER.md`), not the npm package cwd. |
| Drop directory | `operator-assets/human/` (tracked README; `*.glb` gitignored) |

When the resolved path is under the operator root, structure stills report `face_asset: "operator"` (and `face_rig_detail.asset_kind: "operator"`). Fixture paths report `face_asset: "fixture"`.

## 3. Operator Workflow

1. Sculpt or import a production-quality neutral face mesh (target 20k–40k tris — see topology checklist). **Declared** quality target only; no such mesh ships in-repo.
2. Rig the mesh with required bones and blendshapes ([FACE_RIG_SCHEMA](./ENGINE3D_FACE_RIG_SCHEMA_v1.0.md)).
3. Export GLB files named `HumanFaceNeutral.glb` and `HumanFaceRigged.glb` (see Blender export preset).
4. Install into the operator drop path (preferred — does not overwrite CI fixtures):

```bash
npm run operator:face-install -- path/to/HumanFaceRigged.glb
npm run operator:face-install -- path/to/HumanFaceNeutral.glb
```

   Or copy manually into `operator-assets/human/`. Overwriting `mrs/assets/human/` fixtures still works but is discouraged for production deploys.
5. Validate: `cd mrs/packages/engine3d-core && npm run validate:face-glb -- ../../../../operator-assets/human/HumanFaceRigged.glb` (or the install script runs this for rigged assets).
6. Redeploy MRS with the operator volume/env; no API or engine changes required.

## 4. CI vs Production

| Context | Asset | Notes |
|---------|-------|--------|
| CI / demos | Low-tris **fixtures** under `mrs/assets/human/` | Regenerated by `npm run build:face-fixture`; canonical baseline |
| Production | High-tris **operator** assets under `OPERATOR_ASSETS_ROOT/human/` | Same filenames; runtime override |

Tests MUST NOT depend on polygon count. Validation fails only on missing required bone / blendshape names.

## 5. Invariants

- Asset filenames and paths remain constant (logical names).
- Rig structure (bone and blendshape **names**) remains stable.
- Engine3D and public APIs remain unchanged when assets are swapped.
- Soft-raster structure stills record `face_rig`, `face_asset`, and optional `face_rig_detail` / `face_pose` evidence — they do not invent photoreal skin.
- Operator GLBs are gitignored; fixtures remain the CI source of truth.

## 6. Governed polish path (prepared)

Portrait polish expects Engine3D beauty PNG as the structure conditioning image, then optional refine, with RT4D limited to non-face background / lattice. Flux Shell / NIM safety internals are **not** claimed as enforced MRS code; treat black or masked polish outputs as operator pipeline diagnostics unless proven otherwise in-repo.

## 7. Docker / Render volume bake

Do **not** bake production GLBs into the container image. Mount at runtime:

```bash
docker run -v /host/operator-assets:/operator-assets \
  -e OPERATOR_ASSETS_ROOT=/operator-assets ...
```

Root `Dockerfile` copies fixtures only (`mrs/assets` → `/app/assets`) and documents the optional `/operator-assets` mount. Render.com / compose: attach a persistent disk or secret-store sync into `/operator-assets/human/`.
